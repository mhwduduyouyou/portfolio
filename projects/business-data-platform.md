# 企业日报数据自动化与可视化平台

**阶段：生产运行** · **首份真实业务数据：2026-07-29** · **三档无人值守上线：2026-08-27**

## 业务目标

自动采集企业业务日报，完成清洗、缓存、校验、可视化与导出，减少重复人工取数和错误覆盖。

## 我的职责与技术

作为唯一人类开发参与者，与 Codex 协作完成采集架构、数据规则、看板和上线迭代。主要使用 Python、Playwright、Edge CDP、SQLite、PyQt5/QWebEngine、ECharts、Flask 与 Windows 计划任务。

## 已核实成果（截至 2026-10-15）

- 覆盖 **6 家公司账套、13 条业务线**，其中 **10 条**支持自动采集；累计积累 **21,293 行**结构化明细，覆盖 **141 个**业务日期。
- 每日 **08:30 / 13:20 / 20:10** 三档计划任务；累计 **55 轮**运行记录：成功 43、失败 2、跳过 10。
- 一轮约 **830–950 秒**完成 **5–7 条**业务线的采集；提供桌面与 Web 数据看板及 HTML、Excel、PNG 导出。
- 美团数据采集作为同一平台的扩展模块，实际范围按已部署记录区分。

## 代表性工程难点

在目标系统业务 API 不可用时，改用 DOM 采集。针对虚拟滚动重复行、汇总字段和明细混算、碎片行等问题，采用业务行键去重、数据暂存校验和原子提交，避免失败采集覆盖旧数据。

**面试可讨论：** 为什么采集到的数据不能直接覆盖缓存？如何区别成功、失败和跳过的调度记录？
