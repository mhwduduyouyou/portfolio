# OCR 单据智能识别与审核系统

**阶段：生产运行** · **首次服务运行：2026-07-20** · **2026-08-10 起持续承接实际上传**

## 业务目标

对多类型业务单据的图像进行文字识别、结构化字段匹配和人工审核，使识别结果能够进入可追溯的业务处理流程。

## 我的职责与技术

作为唯一人类开发参与者，与 Codex 协作设计并交付系统，负责识别链路、问题分析、部署验证和上线后的用户反馈迭代。技术涉及 Python、Flask、RapidOCR/ONNX Runtime、PaddleOCR 领域续训、OpenCV、SQLite 和双 T4 GPU。

## 已核实成果（截至 2026-10-15）

- 累计上传 **6,879 张**影像（约 **23.3 GB**），执行 **6,885 次**识别；其中包含三轮合计约 5,076 张的批量处理，日常实际量级约 **20–80 张/天**。
- 使用 **3 类**业务单据模板；建立人工修正回流，累计记录 **266 条**修正。
- 在专项评测口径下，端到端字段正确率经多层优化由 **11% 提升至 67%**，不代表全部生产单据的总体准确率。
- 生产健康检查显示双 GPU 池 **2/2** 引擎正常，无 CPU 降级（核查时点）。

## 代表性工程难点

手写车号、司机姓名与数字汉字混排可能出现粘连及吞字。针对这一问题，结合识别参数、字段分配、领域模型续训和规则纠偏优化。部署侧通过 GPU 引擎池控制显存与实例竞争，排查跨池漂移和池空恢复问题。
